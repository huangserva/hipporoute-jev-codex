# T3/T4 Tuning Benchmarks Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在同一修复版本上分别测量 luna effort 与 Jev 置信度门槛对通过率、请求轨迹、墙钟和费用的影响。

**Architecture:** 生产策略只新增默认仍为 `max` 的 `routing.luna_effort`。新增一个调参驱动复用现有任务执行、检查、usage 计价和配置恢复函数，以 task×repeat 内轮转参数档位；每个样本在 health 就绪后开始计时，运行数据写入 gitignored runtime。

**Tech Stack:** Python 3.11+ 标准库、unittest、Codex CLI 0.155.1、真实 Jev/ChatGPT Responses。

---

### Task 3: 调参基准驱动

**Files:**
- Create: `bench/run_tuning.py`
- Modify: `tests/test_bench.py`, `bench/run.py`, `bench/run_subagent.py`

1. 测试三档/两档轮转调度、路由配置覆盖、熔断 gate 判为基础设施失败、T3/T4 聚合字段。
2. 实现可恢复的 `--experiment t3|t4` 驱动；每样本最多重试两次基础设施失败，任务失败不重试。
3. T3 保存逐请求 output tokens（Responses total，包含 reasoning）和 total_ms；T4 保存每线程 Jev 原始选择/置信度/实际模型/fallback 与固定 token 重定价差额。
4. 运行全量离线测试，提交 `新增T3T4：调参基准驱动与统计`。

### Task 4: T3 全量实验

**Files:**
- Create: `docs/experiments/2026-09-20-T3-luna-effort.md`

1. 记录配置 SHA，运行 6 个机械任务 × 3 effort × 3 遍 = 54 个有效会话。
2. 审计每个样本通过、真实模型、effort、completed、请求级输出/耗时及重试。
3. 汇总通过率、请求数、每请求输出、墙钟、费用；引用旧 shadow 数据并明确非同批。
4. 写报告及“能说明/不能说明”，提交 `完成T3：luna effort调参基准`。

### Task 5: T4 全量实验

**Files:**
- Create: `docs/experiments/2026-09-20-T4-置信度门槛.md`

1. 在同一代码提交上运行 4 个 fan-out × 2 threshold × 3 遍 = 24 个有效会话。
2. 审计父子线程数、原始选择/置信度、实际模型、fallback、completed、通过率、费用与墙钟。
3. 单列原始 luna 且 confidence ∈ [0.35,0.5) 的线程，核对 0.35 组实际模型与所属会话通过结果。
4. 汇总回退次数、固定 token 重定价额外费用、总费用和通过率，写局限，提交 `完成T4：置信度门槛调参基准`。
