# 机械任务路由收益基准设计

## 目标与选择

本基准隔离“任务开头选一次模型”的收益，不测试跨轮切换。8 个任务分别在全新 Codex 会话和全新临时工作副本中执行；6 个机械任务预期 luna，2 个推理任务预期 astra。每种模式重复三次，shadow/live 成对且交替先后顺序，共 48 个有效会话。

比较过三种做法：复用一条长会话会重新引入缓存切换成本，固定 mock 工具轨迹不能衡量真实 Agent 行为，只看首请求则忽略完成任务的总成本。选择独立真实会话，以自动验收结果作为质量约束，并汇总会话内所有请求的 usage。

## 数据流

`bench/tasks.json` 声明任务类别、人工预期档位、单句提示、可选的确定性 fixture 变换和通过条件。`bench/run.py` 负责：创建 runtime 目录；备份并临时改写 Codex provider；启动直连路由器并确认 `jev_key=true`；按平衡顺序切换 shadow 哨兵；为每次尝试复制干净工作树；运行一个新的 `codex exec`；从决策 JSONL 的字节增量取出该会话全部请求；运行验收条件；计算 token 和费用；删除工作副本。所有恢复动作放在 `finally`。

基础设施失败（Codex 非零退出、没有首决策、no_key/Jev error、上游非 200）最多重试两次；任务本身验收失败是有效质量结果，不重试。缺少 `response.completed` 的请求进入 `missing_completed` 计数，费用被标为下界而不是静默忽略。

## 统计

每条结果保留任务、模式、重复、尝试、Jev tier/depth 及置信度、真实模型分布、请求数、完整/缺失 completed 数、三类 token、费用、Jev 耗时、墙钟时间、退出码和通过状态。汇总使用每个任务×模式的费用中位数和范围；机械/推理分组先按配对样本求总费用，再报告 live 相对 shadow 节省率；同时报告通过率和 Jev tier 与人工预期不一致项。

原始数据与会话输出只写到被忽略的 `runtime/bench/`，仓库只提交任务定义、驱动、测试和最终报告。
