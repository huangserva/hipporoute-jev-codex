# T2 缺 completed 与 T1 长父线程 fan-out 设计

## 目标与顺序

严格先 T2 后 T1。T2 先为上游 SSE 建立可审计的原始字节证据，用真实 fan-out 会话定位 `response.completed` 缺失在上游、路由器、代理还是客户端边界，找到根因后才修复。T1 只使用 T2 修复后的路由器计费，比较长父历史在 shadow、live/full-history 和 live/no-history 三种设置下的子线程冷读与费用。

## T2 原始流证据

路由器在“从上游 `HTTPResponse.read1` 取得字节”后立即写捕获文件，然后才交给 `SSEUsageTracker` 并写给下游。这个位置可以区分：

- 原始文件没有 completed：上游未发，或路由器在读取完成前停止；
- 原始文件有 completed、tracker 日志没有：SSE 解析问题；
- tracker 有 completed、客户端没有：下游写或客户端终止问题。

捕获只在 `[paths].stream_debug` 哨兵存在时启用，目录由 `[paths].raw_stream_dir` 配置。每条 HTTP 流单独一个 0600 JSONL，文件名由时间和随机 request id 构成，避免把 thread id 写进路径。记录 `start/chunk/upstream_eof/client_disconnect/upstream_error/end`；每个 chunk 有序号、wall-clock、monotonic ns、长度和 base64 原始字节。文件不记 header、请求 body 或 key。

读取环路同时记录客户端写入是否失败。若客户端断开，路由器应继续排空上游到 EOF，仍将字节送入 tracker，但不再写已断开的下游。这既保留 usage 证据，也不改写给正常客户端的字节。只有实测证明缺失正是由客户端断开导致时，才实施这个修复。

## T1 长上下文基准

基准驱动预生成确定性 UTF-8 文本 fixture，内容为编号记录和简短事实，不含 key 或项目隐私数据。父 agent 按清单逐个读文件并用简短回复确认，最后一个 spawn 请求之前的父线程 `response.completed.usage.input_tokens` 是实际父上下文；目标为约 30k/80k/150k，文件数与大小先用 dry run 校准。

每个上下文档运行三种设置：

1. `shadow_all`：路由器记 would，实际父子均 astra，spawn 保持 `fork_turns=all`；
2. `live_all`：实际分档，spawn 保持 `fork_turns=all`；
3. `live_none`：实际分档，在临时工作副本写项目级 `.codex/hooks.json` 和标准库钩子，matcher 为 `.*spawn_agent`，PreToolUse 只把 `updatedInput.fork_turns` 设为 `none`。`codex exec` 增加 `--dangerously-bypass-hook-trust`，不改 model 或 effort。

三档×三设置×三遍共 27 会话，用旋转顺序交错设置。每个子线程直接从决策日志的第一条 `subagent_first` 请求取 input/cached token，计算 `cached/input`命中率；按父/子拆分费用、模型、Jev 决策、通过率和墙钟。任何缺 completed 单独记录并把该样本费用标记为下界。

## 清理与失败处理

两个驱动均用 `try/finally` 恢复 `~/.codex/config.toml`并校验 SHA-256，停路由器，删除 shadow/debug/off 哨兵和工作副本。项目钩子只存在于每次 `live_none` 的临时副本，会随副本一起删除。基础设施失败最多重试两次，失败 attempt 保留在 Git 忽略的 runtime 数据中。
