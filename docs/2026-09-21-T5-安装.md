## 安装与还原

首次安装或更新代码后重装服务：

```bash
cd <home>/development/Jev/codex-jev-router
scripts/install-service.sh
scripts/enable.sh
```

`enable.sh` 的安全顺序是：

1. 检查服务；不健康时先安装/重启；
2. 要求 health 同时包含 `ok=true` 和 `jev_key=true`；
3. 保存唯一的带时间戳恢复点；
4. 先建立 shadow 哨兵；
5. 最后才把 `model_provider` 切到本地路由器。

因此服务没起来、key 没加载时不会把 Codex 指向死端口。普通一键还原：

```bash
scripts/disable.sh
```

它会完整还原备份、删除 shadow，服务留作待命。要同时停服务：

```bash
scripts/disable.sh --stop-service
```

disable 会核对当前配置仍等于 enable 写入的 SHA-256；如果一周内手工改过配置，它会拒绝覆盖并给出备份路径。只有明确愿意丢弃后续手改时才运行 `scripts/disable.sh --force`。

1. 按 `⌘Q` 完全退出 ChatGPT，不只是关窗口；重新打开，因为 App 只在启动时读取 Codex 配置。
2. 在 App 的 Codex 中新建任务，例如“只回复 `T5_GUI_OK`，不要调用工具”。
3. 立即运行下面的只读检查；它不打印 task 文本、token 或认证 header：

```bash
cd <home>/development/Jev/codex-jev-router
python3 - <<'PY'
import json
from pathlib import Path
p = Path.home() / ".codex/codex-jev-router/decisions.jsonl"
```

验收标准是出现与操作时间一致的新线程，首次请求 `gate=apply`（后续新轮可能是 `apply/hold`）、`shadow=true`、`model` 与 `upstream_model` 都是 `gpt-6-astra`，同时 `would` 保存 Jev 希望使用的档位。

如果完全重启后没有新增行，先用报告中已验证的 App 包内命令确认二进制仍读配置；若包内命令成功而 GUI 仍绕过，说明当前 GUI 宿主没有沿用该 provider，不能把它记成通过，临时继续使用 Codex CLI/包内 CLI 并保留日志排查。若出现 401，保持 `requires_openai_auth=true`，检查 `/Applications/ChatGPT.app/Contents/Resources/codex login status` 并重新登录 ChatGPT；不要改成 API key，也不要把凭据写入 provider 配置。

## 三种应急操作

### 1. 路由器挂了

KeepAlive 会自动重启。先检查：

```bash
curl --noproxy 127.0.0.1 -fsS http://127.0.0.1:4319/health
scripts/watchdog.sh
tail -50 ~/Library/Logs/codex-jev-router.err.log
```

watchdog 先调用 launchd kickstart；如果当前用户 launchd 域不可用，会带 7897 代理直接 `nohup` 启动。仍不健康就立刻 `scripts/disable.sh --stop-service`，让 Codex 回到安装前配置。

### 2. 临时关闭 Jev 判断但保留转发

```bash
touch ~/.codex/codex-jev-router/router.off
```

这会 fail-open 到 astra@medium，仍经路由器转发。恢复 Jev 判断：

```bash
rm -f ~/.codex/codex-jev-router/router.off
```

### 3. 一周后真开路由

先确认 `router.off` 不存在，再删除 shadow：

```bash
rm -f ~/.codex/codex-jev-router/router.off
rm -f ~/.codex/codex-jev-router/router.shadow
```

这一步不需要重启服务或 App；之后新边界决策会真实应用 Jev 档位。

## 能说明什么、不能说明什么

当前证据说明 launchd、7897 代理、`~/.jev.env` key 加载、Codex provider、订阅鉴权、Jev 判断、shadow 覆盖、SSE completed/usage 和可逆配置链路都已工作，也说明 App 包内 Codex 与 CLI 使用同一配置协议。
