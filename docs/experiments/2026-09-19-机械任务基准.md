# 机械任务基准：任务开头路由的真实收益

一句话结论：在 8 个任务、每种模式各 3 遍的 48 个全新 Codex 会话中，真路由与全 astra shadow 均为 100% 通过；真路由把机械任务费用降低 **95.36%**、全任务费用降低 **44.75%**，但推理任务费用反而高 **5.60%**，且 live 的会话中位墙钟从 54.2 秒增至 97.6 秒。

## 实验设计

- 任务集：`bench/tasks.json`，6 个机械任务、2 个推理任务；每项都有文件内容、AST、命令退出码、输出正则或精确清单检查。
- 每个样本都是全新的 `codex exec` 会话，没有第二用户轮次，因而不会发生中途换模型和跨模型冷读上下文。
- 模式：shadow 始终由 `gpt-6-astra@medium` 服务但记录 Jev 的 `would`；live 应用 Jev 决定。
- 每个任务每种模式各跑 3 遍，共 `8 × 2 × 3 = 48` 个正式样本。每一任务对的模式顺序交替，每一重复也翻转首发模式。
- 正式运行前进行了两轮 dry run。第一轮发现自动判定器只接受 `20000`、不接受模型合理写出的 `20,000`；以失败测试复现后改成正则检查，第二轮 4/4 通过才开始全量。
- 上游为 ChatGPT Codex 直连，路由器遵守本机 `HTTPS_PROXY`。Jev key 只从 `~/.jev.env` 加载，未写入仓库或运行数据。
- 定价采用 `jev-codex-router/BACKTEST.md`：astra 为 `$10/$1/$50`，sol 为 `$4/$0.4/$20`，luna 为 `$0.2/$0.02/$1.2`，依次是每百万 uncached input / cached input / output token。

费用计算为：

```text
((input_tokens - cached_tokens) × input_price
 + cached_tokens × cached_input_price
 + output_tokens × output_price) / 1,000,000
```

## 核心结果

| 分组 | shadow 费用 | live 费用 | live 相对 shadow | shadow 通过率 | live 通过率 |
|---|---:|---:|---:|---:|---:|
| 机械任务，18+18 会话 | $5.794654 | $0.268790 | **节省 95.36%** | 100% | 100% |
| 推理任务，6+6 会话 | $5.824068 | $6.150096 | **多 5.60%** | 100% | 100% |
| 全部任务，24+24 会话 | $11.618722 | $6.418886（下界） | **节省 44.75%** | 100% | 100% |

live 有一个 luna 工具续跑的 HTTP 200 流没有观察到 `response.completed`，所以 `$6.418886` 是下界。该会话最终完成并通过自动检查；缺失流被显式记为 `missing_completed=1`，没有静默丢弃。

## Jev 判断与人工预期

| 任务 | 人工预期 | Jev 原始 tier（6/6） | tier 置信度范围 | 门槛后策略 | 判断 |
|---|---|---|---:|---|---|
| `m1_rename_local` | luna | luna | 0.97–0.98 | luna | 一致 |
| `m2_add_docstring` | luna | luna | 0.96–0.98 | luna | 一致 |
| `m3_fix_typo` | luna | luna | 1.00 | luna | 一致 |
| `m4_extract_constant` | luna | luna | 0.86–0.91 | luna | 一致 |
| `m5_run_tests` | luna | luna | 0.98–0.99 | luna | 一致 |
| `m6_python_line_manifest` | luna | luna | 0.95–0.97 | luna | 一致 |
| `r1_policy_boundaries` | astra | astra | 0.56–0.66 | astra | 一致 |
| `r2_sse_completion_paths` | astra | astra | 0.24–0.31 | sol | 原始判断一致，但低于 0.5 门槛，策略回退 sol |

因此，按 Jev 的原始 tier choice，8 个任务都与人工预期一致；按最终实际策略，`r2_sse_completion_paths` 是唯一不一致项。它的 depth 仍为 `high`（置信度 0.75–0.80），且 sol 的 3 个 live 样本全部通过，说明这条保守回退没有在当前自动条件下造成质量损失。

每个新会话只在首请求问 Jev，共 48 次。Jev 延迟中位数 825 ms、平均 961 ms、范围 636–1845 ms；本轮没有超过 4 秒，也没有触发重试。此前真实端到端曾观察到一次 6.7 秒冷启动并在超时后重试成功，因此本基准不能否定冷启动风险。

## 真实模型、请求和用量

`response.completed.response.model` 汇总提供了模型真正切换的硬证据：

| 模式 | 上游已完成请求 | 真实模型分布 | input_tokens | cached_tokens | output_tokens |
|---|---:|---|---:|---:|---:|
| shadow | 132/132 | astra 132 | 3,175,515 | 2,494,592 | 46,298 |
| live | 302/303 | luna 230、astra 27、sol 45；另 1 条未知 | 8,681,071 | 7,860,480 | 128,514 |

shadow 的 132 个 completed 全部报告 `gpt-6-astra`。live 的所有有 completed 的请求都与线程钉住档位一致：六类机械任务为 luna，policy 边界分析为 astra，SSE 审计为 sol。缺 completed 的唯一一条是 `m1_rename_local` 第二遍 live 的 luna `tool_continuation`，HTTP 状态 200、会话通过，但其 model 和 usage 无法硬证明或补算。

live 虽然 input/output token 和请求次数显著更多，仍因 230 个请求使用 luna 而大幅省钱。这也解释了为什么“固定 token 后按价格重算”不足以代表 Agent 的真实收益：换模型会改变工具调用轨迹和总 token。

## 墙钟时间

| 分组 | shadow 中位数（范围） | live 中位数（范围） |
|---|---:|---:|
| 机械任务 | 49.6 秒（28.3–62.8） | 84.9 秒（37.7–192.5） |
| 推理任务 | 233.8 秒（182.8–305.3） | 311.2 秒（236.4–454.9） |
| 全部任务 | 54.2 秒（28.3–305.3） | 97.6 秒（37.7–454.9） |

机械任务上，luna 的成本优势伴随明显时延代价；最突出的 `m4_extract_constant` 三次 live 为 143–192 秒，而 shadow 为 48–56 秒。这个版本的路由目标只对模型成本做决策，没有把用户等待时间纳入效用函数。

## 失败、重试和发现的问题

- 正式运行 48 个结果对应 48 个 attempt，没有 ChatGPT/Jev 基础设施失败，也没有触发最多 2 次的重试。
- 48 个任务自动判定全部通过。
- 1/435 条正式上游请求缺 `response.completed`；驱动把该会话费用标为下界。这个现象与上一轮真实端到端中观察到的 HTTP 200 工具续跑缺 completed 一致，尚不能判断是上游未发、客户端提前结束还是终止事件未被识别。
- dry run 发现并修复了数字格式过严的基准判定器 bug，增加了 `file_regex_all` 测试与实现；这不是路由器核心转发 bug。
- 基准汇总补充了 token、请求数、缺失 completed、墙钟、Jev 延迟、总费用，以及“原始 Jev 不一致”和“门槛后策略不一致”两类字段。

## 这个结果能说明什么、不能说明什么

能说明：

- 在“每项工作从全新线程开始、开头只选一次模型”的条件下，机械任务确实能稳定落到 luna；18 个 live 机械样本全部通过，合计费用比 astra 对照低 95.36%。
- 针对上次失败原因，独立新会话消除了 luna→astra 中途升级和 astra 冷读长上下文的切换成本；复杂任务不会污染机械任务的线程。
- 路由并非只改请求字段：上游 completed model 确认三档都被真实使用。
- 0.5 置信度门槛会把“不自信的 astra”变成 sol；本组 r2 样本仍全部通过，但这是需要持续校准的策略行为。

不能说明：

- 48 个会话只覆盖一个代码库、8 种任务和每格 3 次，不能外推到所有仓库、语言、长任务或生产分布。
- 自动通过条件验证的是指定结果，不等于全面代码质量；特别是两份分析报告只检查了关键内容覆盖，没有人工逐篇评分。
- shadow 与 live 是非确定性的独立 Agent 轨迹，不是配对复用同一工具轨迹；推理组多花 5.60% 可能来自请求数和输出差异，不能单独归因于模型单价。
- live 有一条缺 completed，真实总费用略高于已报告下界；不过该条属于低价 luna 工具续跑，不太可能逆转机械组的数量级结论。
- 本轮 Jev 都是热路径 0.6–1.8 秒，不能代表首次建连、代理抖动或 4 秒超时重试的尾延迟。
- 结果证明了费用收益，但也显示 live 时延更高；是否值得上线取决于对成本、等待时间和质量的共同权重。
