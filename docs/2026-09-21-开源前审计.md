# 开源前密钥与隐私审计

一句话结论：当前工作区可以在完成本文所列检查后公开；未发现 TypeSafe
key、caller secret、Bearer/JWT 或 ChatGPT 登录态，但可达 Git 历史仍保留
作者身份元数据、旧 home 绝对路径、实验配置哈希和曾误跟踪的 `pyc` 路径，
如果仓库公开时要求匿名或不暴露这些历史信息，应先重写历史。

## 审计边界与方法

审计覆盖当前工作区、所有 Git 跟踪文件、所有 refs 的完整 `git log -p`、
提交 author/committer metadata、忽略文件规则，以及真实协议 fixture。主要扫描：

- `API-key-` 前缀和当前本机 TypeSafe key 的精确字节串；
- 当前 caller-secret 的精确字节串；
- `Authorization: Bearer`、JWT、access/refresh token 和 ChatGPT account 字段；
- 邮箱、作者用户名、home 绝对路径、主机名、UUID/线程 ID 和长哈希；
- `runtime/`、JSONL、线程状态、本地配置、服务配置和备份是否被跟踪。

两个真实 secret 只用于内存中的精确匹配，命令输出只记录命中数，secret
本身没有被打印、复制或写入仓库。

HEAD 的报告中删除。提交对象自己的 Git object ID 不属于这项清理范围。

## 是否需要重写历史

没有发现 secret，所以不存在因凭据泄露而必须紧急重写历史的理由。但如果
公开仓库不能暴露旧 home 路径、私人 Git 邮箱或实验机器指纹，则需要在发布
前重写。本文没有执行该操作，因为重写会改变所有提交 ID，必须由仓库所有者
决定并协调 force-push。

建议先建立镜像备份，然后在仓库外准备 replacement 和 mailmap 文件：

```bash
git clone --mirror <repository-url> codex-jev-router-backup.git

# /tmp/replacements.txt 中填写真实旧值；不要提交该文件。
printf '%s\n' \
  'literal:<old-home-path>==><home>' \
  'literal:<old-config-sha256>==><redacted-sha256>' \
  > /tmp/replacements.txt

# /tmp/mailmap 中填写旧身份和希望公开的新身份；不要提交该文件。
printf '%s\n' \
  'Public Name <public@example.invalid> Private Name <private-email>' \
  > /tmp/mailmap

git filter-repo --force \
  --replace-text /tmp/replacements.txt \
  --mailmap /tmp/mailmap \
  --path-glob '*/__pycache__/*' \
  --path-glob '*.pyc' \
  --invert-paths

# 重新做本报告中的全历史扫描，再由所有者确认后推送。
git push --force --all
git push --force --tags
```

如果保留实名提交历史是有意选择，只需公开当前 HEAD；旧路径和哈希仍会通过
GitHub 的历史浏览与对象访问可见，这一点应被视为已知且接受的披露。
